# Contributing to rer-dsp-job-geo-file-generation

Thank you for your interest in contributing to the DSP geo-file generation job.

This repository is the batch module of the **DSP (Data Sharing Platform)**,
part of the Rural Environmental Registry (RER). It pre-generates territorial
download files (levels 2 and 3) and publishes them to S3-compatible object
storage.

Please read the [Code of Conduct](CODE_OF_CONDUCT.md) before participating.

Full project documentation lives in
[dsp-docs](https://github.com/Rural-Environmental-Registry/dsp-docs).
The guide below covers this module only.

---

## What belongs here

Changes to pre-generated download files belong in this repository:

- Spring Batch job under `br.car.dsp_geo_file`
- Exporters for each file format (`GeoFileExporter`)
- Tests under `src/test/java`
- Job configuration in `src/main/resources/application.properties` (overrides via environment in Docker)
- This module's `README.md`

The job reads territories pending regeneration from `dsp-db` and features from
`dsp-geoserver-db`. It publishes CSV and GeoPackage to the bucket. It clears
`requires_s3_file_regeneration` only after every enabled format for that
territory is published. It does not create the bucket, does not read the
adopter source database, and does not serve downloads to the browser.

Other DSP work belongs in its own repository:

| Change | Repository |
|--------|------------|
| Architecture, installation, and platform guides | [dsp-docs](https://github.com/Rural-Environmental-Registry/dsp-docs) |
| REST API and download responses | [dsp-backend](https://github.com/Rural-Environmental-Registry/dsp-backend) |
| Web interface | [dsp-frontend](https://github.com/Rural-Environmental-Registry/dsp-frontend) |
| Stack orchestration, gateway, object storage, and adopter configuration | [dsp-core](https://github.com/Rural-Environmental-Registry/dsp-core) |
| Source-database migration and regeneration flags | [dsp-job-data-migration](https://github.com/Rural-Environmental-Registry/dsp-job-data-migration) |

Themes and formats come from `downloadThemesConfig.json`, generated by
`dsp-core` (`./config.sh`). When the job runs is defined by `./setup.sh`
(`DSP_GEO_FILE_GENERATION_CRON`), not by this repository.

## How to contribute

### 1. Bugs and features

1. Open an issue describing the problem or the change in the dsp-core repository:
   https://github.com/Rural-Environmental-Registry/dsp-core/issues
2. Fork the repository
3. Create a branch from `develop`: `git checkout -b feat/short-description`
4. Make the change
5. Run the tests: `./mvnw test`
6. Commit with a clear message
7. Open a pull request against `develop`

### 2. Job changes

Keep each step in the package that already owns it:

| Area | Package |
|------|---------|
| Batch job, reader, and writer | `br.car.dsp_geo_file.batch` |
| CSV, GeoPackage, and new formats | `br.car.dsp_geo_file.export` |
| Run progress and orphan cleanup | `br.car.dsp_geo_file.generation` |
| S3 publishing | `br.car.dsp_geo_file.storage` |
| Territory flags and slugs | `br.car.dsp_geo_file.territory` |
| Theme catalogue | `br.car.dsp_geo_file.theme` |

A new format implements `GeoFileExporter` and is listed in the theme
`formats[]`. Backend keys and endpoints stay the same. Level 2 is processed
before level 3. Cover the change with a test in `src/test/java`.

### 3. Documentation of this module

Keep `README.md` limited to this module: purpose, stack, and where it fits.
Platform-wide guides (architecture, quick start, full installation) go to
[dsp-docs](https://github.com/Rural-Environmental-Registry/dsp-docs), in both
`docs/pt-br/` and `docs/en/`.

## Local setup

Requirements: Java 21 and the Maven wrapper already in the repository
(`./mvnw`).

Run the job:

```bash
./mvnw spring-boot:run
```

That needs the three datasources configured in `application.properties` (or via
`SPRING_DATASOURCE_*` / `DSP_OBJECT_STORAGE_*` env vars), a bucket that already
exists, and `dsp-geoserver-db` already filled by the migration job. The
preferred way to run it (SeaweedFS and schedule) is `./setup.sh` in
[dsp-core](https://github.com/Rural-Environmental-Registry/dsp-core), with the
`object-storage` profile.

Run the tests:

```bash
./mvnw test
```

## Code standards

- Java 21, Spring Boot 3.4.2, Spring Batch, Maven, PostgreSQL/PostGIS, AWS SDK v2 (S3)
- Artifact id: `dsp-geo-file-generation`
- Source encoding is UTF-8
- Package root: `br.car.dsp_geo_file`
- The process has no HTTP port (`spring.main.web-application-type: none`)
- Connections stay `batch` (schema `geo_file_generation`), `target` (`dsp-db`, schema `dsp`), and `geo-target` (`dsp-geoserver-db`)
- Spring Batch schema initialization stays `never` (`spring.batch.jdbc.initialize-schema`)
- Object storage is configuration. The job does not create the bucket
- Features are read from `dsp-geoserver-db`, the same base GeoServer Download uses for WFS

## Review process

1. **Tests** — `./mvnw test` must pass
2. **Peer review** — at least one maintainer reviews the pull request
3. **Merge** — approved pull requests are merged into `develop`

---

## Commit message format

Use conventional commits:

```
feat: export GeoPackage when the theme lists gpkg
fix: keep the regeneration flag when one format fails
test: cover level 3 object keys with the parent slug
docs: describe local spring-boot:run in the module README
```

**Types:**

- `feat:` — new behavior
- `fix:` — bug fix
- `test:` — tests only
- `docs:` — documentation only
- `refactor:` — internal change with the same behavior
